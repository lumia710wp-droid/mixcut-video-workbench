# 按脚本检索素材

## 为什么分为程序检索与 Codex 判断

程序能遍历数千条索引、验证商品和版本、查词、排序、分页及排除占用；Codex理解脚本，将要求变成画面问题，再依据已完成的事实标记比较候选和规划叙事。有效标记足够时不重复看原片；信息不足才补查。候选分数只表示词面/同义词命中，不代表最终选择。

当前检索使用 JSON 文件倒排索引、中文双字组、英文词及受控视觉同义词，无数据库、向量服务或外部模型。它不等于向量语义检索，不能保证跨所有说法召回；未命中时先检查标记覆盖和检索表达。若以后确有漏检证据，再扩充词表，不以泛化词替代商品/动作事实。

## 1. 脚本拆成画面需求

例句：“把芒果果肉包进白皮，捏好收口。”可拆为放入果肉、包拢、收口三个可见需求；不一定三个镜头，一个真实连续动作也可覆盖。记录：

```json
{"need_id":"N02","script_quote":"把果肉包进白皮，捏好收口","role":"制作过程",
 "match_mode":"literal","goods_id":"芒果","must_see":["放入果肉","包拢"],
 "alternatives":[],"target_duration_sec":3.0,"status":"searching"}
```

“下午想吃点软糯的”属于销售氛围，不需要检索“下午”“软糯”这种不可直接验证的动作。可以检索同一商品的果肉、成品或制作细节，写明是辅助画面，不声称画面证明口感、配方或时间。

## 2. 程序内的索引与过滤

索引单元是**源文件中的观察阶段**，不是整个源的一段笼统描述。源摘要中的“包装”不能让该源每个阶段都命中包装。每个索引条目绑定源ID、源hash、事实hash、阶段号、源时码、阶段观察、动作点和质量；商品确认、版本和证据仍以原始事实/目录为准。

构建时只生成派生缓存；未变更阶段复用文档，无变化时不重建。源或确认记录变化后查询明确报索引过期。原事实、旧批准和原片不写回。查词前/后以当前商品范围、项目素材范围、风险、有效事实版本和已有预占限制候选。

## 3. 查询不是一段长文

先查一个具体动作，例如“放果肉”，不要直接塞整篇旁白。把不可放宽的动作放入 `must`，不想要的干扰放入 `exclude`；普通 `query` 提供较宽的召回。例：

```json
{"brand_id":"示例品牌","goods_id":"芒果","query":"放果肉",
 "must":["放果肉"],"exclude":["遮挡"],"min_duration_sec":1.5,
 "limit":6,"max_per_source":2,"max_output_chars":6000}
```

`group_id` 可关联实际项目的排除源和约束，不能借此跨品牌/商品。检索可用时长指剩余源时长；若后续用1.1倍播放，检索源时长须覆盖成片需要的1.1倍。

## 4. 可解释排序和少量返回

倒排表先召回可能命中的阶段，再检查必需动作、排除词、可用区间和预占。排序依据视觉同义概念和字词命中，再对明确失焦/遮挡等说明粗略降权；同分使用稳定ID排序。每源限制候选数，避免一份源占满列表。

每次最多12条，常用6条；字符预算1800—12000，常用6000。程序同时执行条数和实际序列化字符数上限，不靠描述“尽量简短”。下一页通过 `next_cursor`，绑定查询、素材版本与预占状态；状态变化须从首页重查。

候选时间段是定位范围，不是批准切点。已占用区间从候选源区间中扣除，剩余不足所需时长就不返回。Codex依据入库标记和配音时长定切点；稳定阶段内部可直接计算取用区间，允许跨相邻阶段，但不能跨到别的商品或重复占用片段。标记无法支持所需动作衔接或边界判断时才补查。

## 5. 默认复用入库事实，疑点再补查

直接依据有效的阶段、动作、商品和质量标记选择镜头，不重复打开全部候选。`show`可用于读取完整事实文字；其中附带的起/中/末关键帧及审核副本路径是可选追溯入口，不是新的观看任务。

每个常规镜头记录`selection_basis.type=indexed_facts`、`facts_sha256`及`document_id`。程序验证它确实绑定所选源的当前事实；与脚本的匹配和叙事顺序由Codex判断。

仅在标签不确定/矛盾、需要的动作未标清、素材变更，或必须判断的切点/连续性超出标记精度时，补看对应区间或加密帧。1秒采样不证明逐帧边界，但这不意味着每次取整数帧都要重看，稳定阶段内部可按时长直接取片。已标记明显不合适的片段可直接避开。

发生补查才保存`visual_review`，如实记录方式和新证据；复用旧标记不称新审片。额外预览落盘并绑定源hash和时间映射，不拿审核副本当生产原片。新增补查证据仍须由项目接口登记并与所选源匹配。

把补查发现的客观阶段、动作或质量信息按素材整理契约补成新的事实版本，供以后直接复用；取用排名、用途和剪辑参数仍留在编导计划。随后刷新当前受影响的查询和事实引用，不让同一个标记缺口在每批重复触发观看。

## 6. 迭代与缺口

优先顺序：精确动作 → 一个同义表达 → 需求允许的辅助画面。可以分别检索“放果肉”“包拢”“收口”，而不是要求一个阶段同时含所有词。保留原必须项与每次查询变更。

`no_match` 意味着本轮条件未命中，不证明全库不存在；“未见切开”“无法判断切开”也不能当正向切开证据。当前否定词处理只是保守词法过滤；先按事实文字判断，复杂句确有歧义时才补查。

两轮仍不足时明确区分：索引表达缺口、标记未覆盖、时长不足、商品不明确、素材被占用、实际无合适画面。可继续处理其他需求，但不偷偷换商品、虚构动作或自动改写已确认文案。核心动作缺失需要用户决定补拍、改稿或接受辅助画面。

## 7. 编导选择与精确计划

按整条视频的开头吸引力、动作连续性、景别变化和结尾完成感选择，不逐需求机械取第一名。整批同时检查不同开头、相同源区间、相同来源组合和项目要求的独有素材比例。重复动作不是新故事；不同文件也不自动等于不同内容，已知重复组按项目记录排除。

配音有实际时长后才锁时间线。不能用观测阶段范围直接代替切点；计划使用30fps整数帧、左闭右开区间。保存原文映射、事实版本、选择理由、替代与缺口；如有补查再附证据。每次脚本/选材变化形成新版本，重新核对依赖，不能沿用旧批准。

## 8. 上下文与恢复

原始查询、结果、详情和计划放任务目录。每轮只加载少量未解决需求及当前候选；完成的镜头只在检查点保留ID、源区间、理由摘要和文件路径。候选包可翻页，但不要把所有页累积拼接为下一次提示词。

程序报索引过期先增量构建；源确实变化时先更新入库事实，再按需补查；未知编辑结果先读回。不得把结构校验通过、索引生成、审核副本存在解释为新审片或用户批准。
